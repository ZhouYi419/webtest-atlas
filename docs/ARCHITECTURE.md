# WebTest Atlas 技术架构

## 目标与设计状态

覆盖 [PRD](PRD.md) 的站点接入、知识、测试、脚本和结果链路。首版采用本地单用户单环境。T001 已落地的运行边界如下，其他功能随任务验证。

### T001 运行边界

- Windows 运行 DSH Web `0.2.2-rc.5` 与项目的 Python 3.13 MCP stdio 子进程。项目补丁声明 Atlas 预设，启动时核对其实际工具目录。Compose 单独托管静态示例后台，端口绑定到 `127.0.0.1`。SQLite 与 Windows 浏览器位于宿主机。DSH 配置及本地数据位置见 [DSH 运行说明](DSH.md)。
- 读取器只接受固定回环端口的根路径。Playwright 截获主文档请求，取得真实响应时禁止自动跟随跳转，然后把 HTML 交给 Chromium 渲染。子资源请求受限，脚本和服务工作线程禁用。仅通过允许值检查的标题及可见标志进入对话和数据库。
- `runs` 与 `steps` 存储运行和步骤，以运行 ID 及步骤序号定位证据。正在执行的同一首页读取复用运行 ID；所有终态与最后一步在同一事务提交。查询或再次读取时，依据原进程的存活状态和创建标识识别中断。原有运行可继续按 ID 查询。

## 技术选型

| 领域 | 推荐 | 理由与可行替代 |
| --- | --- | --- |
| 对话入口 | DSH Web 原生对话，使用独立项目 profile 装载测试能力。优先验证本地 MCP stdio 工具接入 | 复用现成聊天、模型和会话入口。若需要宿主专属的界面挂载或通知，评估使用 DSH 原生插件注册相同业务能力，并以目标版本公开契约为依据 |
| 执行内核 | Python、Playwright Chromium、pytest | UI、登录态和接口请求分享同一套浏览器自动化工具。仓库已有 Python 3.13 虚拟环境作为试用起点，锁版本前核对实际兼容。若 DSH 和浏览器链路存在 Python 集成成本，再比较 Node.js 与 Playwright Test |
| 持久化 | SQLite 存结构化配置、知识、运行与脚本元数据。本机受限目录存脚本和脱敏证据 | MVP 单用户且查询按环境、实体和最近运行筛选。迁移需要保留历史、脚本引用和证据关系。并发或共享部署有明确需求时再评估 PostgreSQL |
| 本地运行 | DSH 宿主和 Python 工具进程同机联调，Chromium 支持宿主机可视模式。示例 Web 服务通过 Docker Compose 启停 | 人工登录需要可接管的真实浏览器。若服务与宿主运行在不同环境，首个切片验证回环端口、网络权限和进程生命周期 |

上游已公开 Web profile、插件装载及 MCP 接入说明。具体工具注册、进度通知与停止语义以选定版本实测为准。[DeepSeek Harness 仓库](https://github.com/deepseek-ai/deepseek-harness) · [DSH CLI 与 profile 参考](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.md)

## 组成和依赖

```text
DSH 对话 → 插件或 MCP 适配器 → 任务服务 → 执行器 → 目标站点
                                ├→ 知识、脚本和运行记录
                                └→ 授权检查、凭据引用和证据写入
独立脚本入口 → 同一执行规则与断言 → Playwright Chromium / 接口客户端
```

| 组成 | 职责与边界 |
| --- | --- |
| DSH 适配器 | 将对话请求整理为接入、探索、执行、查状态、停止、历史、生成或复跑任务。传递结构化输入与脱敏输出。宿主处理对话，适配器使用测试内核的公开入口 |
| 任务服务 | 校验任务与范围，将用户目标映射为可检查的步骤和断言。查询已验证知识，有明确缺口时组织有限补充探索。记录进度、取消信号与执行结论 |
| 执行器 | 操作临时浏览器上下文或运行已观察、已提供的接口场景。识别登录过期、权限及环境失败。操作前检查授权，记录各步结果、创建的数据和清理状态。封装 Playwright 细节 |
| 项目数据和凭据 | 数据层保存项目资产与运行元数据。凭据提供器仅向执行器解析凭据引用。适配器通过脱敏证据索引展示可公开信息 |
| 脚本导出 | 将经过校验的结构化用例转换为 pytest 可运行包。独立执行所需的依赖、配置示例和运行辅助随包提供，复用与内置执行一致的步骤、断言和授权校验 |

建议随任务建立目录。 `src/webtest_atlas/` 放内核与 DSH 工具接口。确需 Node 侧注册时用 `integrations/dsh/`。 `examples/` 保存合成示例站点和样例， `tests/` 保存回归测试， `docs/` 保存项目文档。数据库、运行证据、脚本工作副本和登录态放在单独的本地数据目录，登录态使用受限存储。具体结构在首个切片按实际依赖最小化落地。

## 数据与运行状态

| 实体 | 核心内容与归属 |
| --- | --- |
| 环境配置 | 站点起始 URL、环境标识、账号别名、凭据引用、业务地址与操作范围、探索预算。登录外部域与页面资源域按用途记录 |
| 项目知识 | 页面或流程标识、已验证入口与定位、接口方法和路径模板、脱敏参数样例、数据依赖、观察来源、证据引用、验证时间及有效性。业务预期有独立记录、来源和修订历史 |
| 用例和脚本版本 | 流程步骤、断言及预期来源、所需配置与数据、清理计划、版本、生成来源、最近验证的运行引用。用例及脚本版本可从一次运行反查 |
| 运行与步骤 | 运行 ID、环境、任务类型、用例版本、进度时间、步骤、证据引用、结论和原因。生命周期建议使用排队、运行、等待人工、完成、停止；业务结论和生命周期分别记录 |
| 测试数据清理 | 本次创建对象的唯一标识或可核对的运行标记、授权清理方式、当前处理状态及错误。保留来源和尚待核对的对象 |
| 凭据与登录态 | 本地凭据提供器和受保护的浏览器会话存储，按环境与账号隔离。引导期间可在本机受限入口录入，选型涉及 Windows 凭据存储或本机安全等效方案 |

- 例如“查询申请列表”经对话进入任务服务，读取环境范围和已验证的页面、参数与业务预期。从测试数据得到已知条目和空结果输入，执行页面步骤和断言，将脱敏证据归档到运行。缺少明确预期时记录已观察的值并给出未判定。业务失败关联具体断言；浏览器异常与登录阻塞各有独立原因。
- 已观察的请求只以业务动作关联的证据进入知识。先精确索引环境、页面、路径和流程，再补充匹配。数据规模和检索结果证明有需要时再引入全文或语义检索。
- 先持久化运行及输入版本，再执行外部操作。终态、步骤与证据引用一致。MVP 串行运行目标站点任务，以环境级执行约束防止并发重复写。重复提交应返回已有运行或明确已排队。重启后识别中断记录，复跑分配新运行 ID 并复用指定版本。
- 写入前分配可核对的运行标记。成功后记录实际对象 ID；写请求响应丢失时先按运行标记核对结果。在无法证明对象归属时记录待处理。停止时停止发起新业务步骤，按已批准清理计划处理确定归属的对象，保留清理结果。浏览器或工具进程异常退出时，重启后展示中断与清理状态。恢复时核对对象再决定后续动作。

## 执行和数据边界

- **目标及操作范围**　每次浏览导航、重定向、业务操作和接口请求都受实际执行侧范围控制。配置区分站点业务地址、允许处理登录的地址和渲染所需资源地址。域、路径或执行能力越界时给出原因。已授权的环境和操作持续有效。探索默认只走已确认无业务副作用的浏览和查询，按操作语义判断授权。
- **工具输入**　网页、接口响应与目标站文本是待测试数据。授权来自用户配置。模型提出的步骤，包括输入、操作类型和目标，经过结构化校验后执行；权限由执行器检查。未知操作按当前权限与任务需要处理，必要时报告阻塞。为 Atlas 对话配置所需工具与权限，验收确认它通过 Atlas 接口操作目标站。
- **登录恢复**　复用受保护的会话状态，以页面或接口的明确登录标志判断是否失效。预算内尝试登录恢复。验证码或 MFA 时打开可视窗口供本人完成。恢复后校验账号和环境，继续待执行步骤。凭据和浏览器状态只在运行端使用。Playwright 认证状态可能含可复用的敏感数据，须验证本地存储权限。[Playwright 认证状态](https://playwright.dev/python/docs/auth)
- **接口执行**　只接受已观察或用户提供的业务接口及明确的授权操作。读取样例准备参数，按接口的合法鉴权方式构造请求。使用浏览器会话复用 Cookie 时，验证目标与会话的授权边界。[Playwright APIRequestContext](https://playwright.dev/python/docs/api/class-apirequestcontext)
- **证据与模型出口**　对话工具结果采用允许字段和脱敏摘要。密码、Token、Cookie 和会话文件禁止进入知识、普通日志、脚本、模型参数和 Git。截图先处理敏感区域，接口只保存允许的字段。原始 Trace 可能带请求内容，仅在受控诊断场景使用，直接交付使用脱敏截图或步骤记录。核对目标 DSH 版本的会话日志与遥测配置，验证项目 profile 的数据外发行为与预期一致。[DSH CLI 日志与遥测参考](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.md#shared-deployment-behavior)
- **脚本一致性**　渲染前验证步骤和断言、导出后的环境配置与权限，使用独立进程实际运行。独立执行继续校验范围和清理归属。允许的修复只修改等价定位和等待，保存前后版本及复验结果。

## 首轮验证与风险

1. **宿主集成最先验证。** 在选定 DSH Web 版本中使用项目 profile，实际调用 Atlas 读取示例站页面。用 Chromium 生成真实结果，新对话读取同一运行。记录宿主版本、配置入口、进度支持与工具断开行为。
2. **登录与网络边界。** 验证宿主可视 Chromium 接管、登录过期、凭据脱敏、跨授权范围的重定向，以及正常页面资源加载。
3. **可信结果。** 使用合成后台改变业务响应，在相同预期下复现失败。区分无预期、鉴权阻塞、浏览器中断和业务不符，检查证据与运行 ID 一致。
4. **可独立运行。** 在独立目录按导出包说明启动，用实际目标配置复跑两次。验证同类断言、测试数据清理和产物无凭据。

任务入口、依赖和验收见 [任务与验收](TASKS.md)。

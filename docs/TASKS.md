## T001｜本地 DSH 对话到浏览器结果

- **目标**　用户能从实际 DSH Web 对话启动一次本地浏览器操作，并查看运行记录。提前验证宿主插件、浏览器及持久化能连通。
- **范围**　检查本机 DSH 及其版本和安装方式，验证项目 profile 与插件或 MCP 工具装载。使用本地合成示例后台的公开页面，执行一次有范围限制的 Chromium 读取。工具返回标题或页面标志、运行 ID、简短结果和步骤证据。建立最小运行记录和历史查询入口。
- **边界**　使用 DSH 原生对话。全站探索、认证和自定义面板有后续任务或按需求细化。确需新增界面时进入相应原型评审。
- **验收**　在浏览器打开实际 DSH Web，输入任务后看到来自示例站页面的真实结果。用新对话或重启进程查询同一运行。示例站不可达时显示阻塞原因，访问超出授权的目标时拦截并记录，浏览器运行异常时显示执行错误。记录宿主版本、安装入口、网络与进程边界、进度可用方式以及日志配置。

### T001 验收记录（2026-11-23）

- 本机为 DSH `0.1.1-rc.2`、Node.js `24.18.0`、Python `3.13.0`、MCP `1.30.0`、Playwright `1.65.2`。Compose 在 `127.0.0.1:18765` 提供合成页面，Windows 上的 Chrome、可视 Chrome 和 Edge 均已测试。Nginx 复用了兼容的本机已缓存镜像。
- 独立 MCP 进程实读标题“Atlas 示例后台”和可见标志“申请列表”。结束该进程后用新进程查询 `d579be05-9fa8-4b3e-b941-a1fd2b97c35b`，完整记录与两步证据一致。
- 暂停 Compose 示例容器后读取返回站点不可达，恢复容器后首页可用。越界路径在发起 HTTP 请求前阻塞，浏览器通道配置错误归为执行错误。另在真实浏览器回归中关闭活动页面，验证了运行中断；目标服务器计数验证了重定向与附属资源拦截。
- 21 项自动回归覆盖真实页面读取、并发去重、事务回滚、旧库升级、进程中断与 MCP 会话切换。额外以官方默认 Nginx 镜像在独立回环端口启动，确认从 Chromium 读到相同页面。
- 原生 DSH Web 使用本机已配置的 DeepSeek-V4-Flash。初次读取暴露出宿主进程选项被 Playwright 继承的问题。原失败记录 `c59b2b0a-c893-4e6f-b906-ca854c2d35b2` 保留。修复后在原会话重新调用 `mcp__atlas__read_demo_page`，运行 `446e133c-a484-405e-871b-420e29d95458` 读到“Atlas 示例后台”和“申请列表”。启动时检查实际工具目录，恰有读取和历史查询两项。
- 在原生 Web 提交越界合成路径，工具返回 `blocked` 及“只允许读取已配置的本地示例站首页”，运行 ID 为 `483c947c-60c3-49d2-876b-f6e7cc404595`。
- 修复本机其他项目的默认预设影响“新会话”按钮的问题。宿主重启后点击该按钮，确认进入空白 Atlas 会话，仅提供上一次成功运行的 ID。DSH 调用 `mcp__atlas__get_run`，返回相同 ID、标题、可见标志和两步证据。已在窄窗口操作并在 1280 像素宽度核对历史结果。完整业务断言、长任务进度与主动停止按后续切片验收。

### T001 宿主升级（2026-11-23）

- 项目从 DSH `0.1.1-rc.2` 切换至 `0.2.2-rc.5`，使用本机 Node.js `24.18.0`。Atlas 定义为新版声明式 Web 预设。独立启动实测仅发布 `read_demo_page` 和 `get_run` 两项 MCP 工具，额外会话日志上传与 OTel 插件已禁用。
- 在真实 3081 Web 新会话选用已确认的 DeepSeek-V4.1-Flash，读取合成示例站得到运行 `13ec3738-7787-4e64-b63e-9a1354830a31`。从另一空白会话按 ID 查回该运行和升级前的 `446e133c-a484-405e-871b-420e29d95458`，两者均返回标题“Atlas 示例后台”、标志“申请列表”和各自原始的两步证据。
- 原有 21 项 Python 回归通过。新增模型映射回归使用 rc.5 自带配置解析器验证官方 Flash、推理等级、其他模型、其他提供方以及自定义网关。npm 已移除旧版专属 npx 安装，保留的新版 CLI 实测返回 `0.2.2-rc.5`。
- 旧版删除后，从正式脚本冷启动 3081，再次打开真实 Chrome。新对话自动选中 DeepSeek-V4.1-Flash，既有凭据可用，升级前后的两条历史仍可查询。独立故障验证确认，默认预设不存在、MCP 无法启动或出现额外工具时，宿主均以状态码 1 退出，Web 端口未开放。

## T002｜配置站点并恢复登录

- **目标**　配置一次站点、授权和账号后，Agent 可登录、复用及恢复登录。
- **范围**　本地配置入口、凭据引用、登录后的明确检查点、受限会话状态；使用受支持的可视 Chromium 处理人工验证码或 MFA 并继续。
- **边界**　首版一个环境和测试账号。实际登录表单、挑战类型及配置交互随任务确认。
- **验收**　提交有效配置后成功登录，重启后复用有效状态，状态过期后尝试恢复。人工挑战只提示当前需要的操作，操作完成后继续。错误凭据和缺少权限分别给出清楚的阻塞原因，普通日志及对话无凭据。

## T003｜探索并持久化项目知识

- **目标**　接入后自动获得可复用的页面和请求知识，用户能查看探索进度或停止。
- **范围**　在已授权的浏览、查询范围内探索菜单、页面和表单，关联实际请求。记录脱敏证据与验证时间，说明预算和覆盖情况。
- **边界**　写操作由已授权的具体测试流程执行。业务预期按明确来源采集。
- **验收**　示例后台的列表、详情、查询表单与查询动作对应的请求被保存。重复导航有界。通过对话停止探索后可查已有进度和结果。新对话可直接使用持久化发现，异常重启可识别中断。

## T004｜对话验证页面查询

- **目标**　从 DSH 对话验证实际列表查询的命中和无结果场景。
- **范围**　复用探索结果和已知测试数据，通过实际 Chromium 页面执行。用户补充的预期自动保存并用于后续断言。结果含关键步骤和脱敏证据。
- **边界**　聚焦查询与详情。外部写入与脚本导出后续交付。
- **验收**　基准站点中命中与无结果均通过。开启示例站的查询错误后，同一场景的断言失败并带证据。缺少业务预期时标为未判定。新对话能复用用户补充的规则。

## T005｜对话验证业务接口

- **目标**　通过对话执行并验证查询接口。
- **范围**　使用观察到或用户明确给出的业务接口，准备已知输入和鉴权，验证响应码及响应字段，保留脱敏请求或响应证据。
- **边界**　以授权的功能测试接口为限。首个案例使用同一示例后台的查询接口。
- **验收**　已认证的实际请求得到断言结果。错误响应、超时、鉴权阻塞分别显示对应原因。目标越界时执行端拒绝，输出省略敏感值。

## T006｜对话验证新建流程与清理

- **目标**　从对话运行“新建测试申请 → 提交 → 查询结果”，并验证清理。
- **范围**　前置校验写权限，生成本次测试数据，保存创建对象、运行标记和清理结果。覆盖部分失败、取消以及可识别的重启中断。
- **边界**　清理仅作用于已授权且可确认归属本次运行的对象。清理不可用时保留待处理信息。
- **验收**　正常运行验证查询可见并清理数据。创建后断言失败、超时或停止时可从记录判断对象与清理状态；账户没有写权限时在副作用发生前阻塞；已有业务数据保持完整。

## T007｜导出并独立运行 UI 脚本

- **目标**　把已运行的 UI 流程变成可在 DSH 之外复跑的测试资产。
- **范围**　将完整步骤和断言渲染为脚本，准备依赖、配置样例及必要的清理，实际验证后保存并导出。使用新建流程验证一个带清理的示例。
- **边界**　首批脚本针对已支持的步骤与断言。扩展待实际用例出现时评估。
- **验收**　在独立目录按说明使用配置引用连续执行两次，并清理本次数据。引入已知业务错误时导出脚本按原预期失败。导出包不含真实凭据及登录状态。

## T008｜导出并独立运行接口脚本

- **目标**　对已运行的接口测试生成可独立运行的脚本。
- **范围**　复用导出、版本和验收入口，保留参数、鉴权配置引用、断言与证据输出。
- **边界**　首个交付覆盖 T005 的查询接口场景。用例具备副作用时沿用 T006 的清理规则。
- **验收**　独立运行两次，能够复现原业务断言。返回字段变化时准确失败，鉴权问题有明确阻塞原因，样例和产物无秘密值。

## T009｜复跑与站点变更适配

- **目标**　在新对话或重启后找到并运行已保存的测试，处理局部页面变化。
- **范围**　从历史或资产发起新运行，优先使用已验证资产，按预算补充局部探索并记录版本。对等价定位和等待调整进行复验。
- **边界**　步骤目的、断言和预期按原版本保留。实际业务预期发生变更时记录用户确认的修订。
- **验收**　复跑有新运行 ID 并关联先前版本。示例站的局部定位变化经过等价修复可恢复，原始失败及修改记录可追溯。切换到已知业务错误时同一断言仍失败。

## T010｜本地安装与 MVP 验收

- **目标**　用户或部署者可依据仓库文档在干净环境安装并使用 MVP。
- **范围**　核对真实的启动、配置和使用说明，补齐安全配置示例、示例站、测试数据与验收记录。
- **边界**　将已验证的平台、宿主和浏览器版本写入 README，其他部署形态随实际验证记录。
- **验收**　在干净的本地环境按文档配置 DSH 和示例站。覆盖首次接入、保留知识、自然语言 UI 与接口测试、脚本独立执行、停止、历史、重启复跑、注入已知业务错误以及无法恢复的登录阻塞。
